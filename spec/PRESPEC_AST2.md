# Pre-specification: AST v2 on a fresh dataset (Bank Account Fraud) -- frozen before any run
Date: 2026-11-26. Follows PRESPEC_AST.md (v1: HS1-HS3 not met on five datasets). v2 is evaluated ONLY on a dataset never used before (BAF, 200k-row systematic 1-in-5 subsample of Base.csv, ordered by month, `month` and label dropped from features; md5 of the gz cac77ca6f43616158b753816f6c3e08d). The five older datasets are not re-used for any claim about v2.
## Changes from v1 (all fixed now; motivated by the post-hoc diagnostic that v1 left the naive threshold unchanged in heavy contamination)
1. Threshold grid spans observed-negative score quantiles [0.02, 1] with 2000 points (v1: [0.5, 1], 1500).
2. Purity model clipped to [0.02, 0.98] (v1: [0, 1]) so inclusion weights stay bounded.
3. Phase-2 sampling weights use a defensive mixture: w <- 0.75 w/mean(w) + 0.25 (v1: w only).
4. A diagnostic code is logged per rule (n_aud = 10*B + code; code 0 normal, 1 fallback to naive because |R|<30 or B<20, 2 fallback because the estimated clean mass was <= 0, 3 no grid point met the budget so the top grid point was used).
Everything else (region u = 2% quantile of labelled positives, B1 = B/2 uniform phase, isotonic purity, Neyman allocation, AIPW estimate, B = max(20, f*n_val) audited items, f in {0.2, 0.5, 1, 2, 5}%) is unchanged. Rules: ast2_f. v1 rules (ast_f), uniform audit (aud_f, audnp_f) and all older rules are recomputed in the same runs. Learners LR/RF/XGB (XGB on GPU via env XGB_GPU=1 for speed: numerical results differ slightly from the CPU version, applied to all rules in the run alike), strategies BASE/CW, noise random/delay/delay2, poison 0/0.2/0.4, ops fpr1 (1%) and fpr01 (0.1%).
## Hypotheses (BAF only; cells = noise x op x poison with poison in {0.2, 0.4} = 12; paired Wilcoxon over window x learner x strategy; Holm within hypothesis; p-values descriptive because units share windows)
HV1 (efficiency): ast2_0.5% and ast2_1% each have lower absolute calibration than aud_0.5% / aud_1% (equal budget), Holm p<0.05, in at least 7 of 12 cells.
HV2 (utility): ast2_0.5% lowers absolute calibration versus naive, Holm p<0.05, in at least 7 of 12 cells.
HV3 (diagnostic, not pass/fail): ast2 versus ast (v1): share of cells with lower mean absolute calibration.
HV4 (reporting): distribution of diagnostic codes; every cell where ast2 is worse than naive.
Verdict rule: v2 is called confirmed on this dataset only if HV1 (both budgets) and HV2 all hold. One dataset cannot support a general claim; a pass would justify a further independent dataset (PaySim), a fail ends the AST line. Nothing is retuned after seeing results.
